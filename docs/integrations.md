# راهنمای یکپارچه‌سازی‌های خارجی — بنکداری هوشمند

همه سرویس‌های خارجی بدون نیاز به دانش فنی و فقط از داخل پنل مدیریت تنظیم می‌شوند:
**پنل مدیریت → منوی «سیستم» → «تنظیمات یکپارچه‌سازی»**

برای هر اتصال یک کارت با وضعیت (متصل/غیرمتصل)، دکمه تست، دکمه قطع اتصال و راهنمای گام‌به‌گام وجود دارد. مقادیر حساس پس از ذخیره فقط به‌صورت `••••••` نمایش داده می‌شوند و با **AES-256-GCM** در دیتابیس رمزنگاری می‌شوند.

---

## ۱) Google Drive — بکاپ خودکار

### روش اول: حساب شخصی Google (ساده‌ترین)
1. Client ID و Client Secret گوگل باید تنظیم شده باشد — از تب «ورود با گوگل» پنل مدیریت داده‌ها یا متغیرهای محیطی. Redirect URI زیر را هم در Google Cloud Console اضافه کنید:
   `https://<دامنه-سایت>/api/integrations/google/callback`
2. در کارت «Google Drive» روش «حساب شخصی» را انتخاب و روی **«اتصال حساب Google»** بزنید.
3. در صفحه گوگل اجازه دو مجوز را بدهید (پروفایل + مدیریت فایل‌های ساخته‌شده توسط برنامه — اسکوپ `drive.file` به کل Drive دسترسی ندارد).
4. حساب متصل اولیه به‌عنوان **مقصد بکاپ** علامت می‌خورد؛ با چند حساب می‌توانید مقصد را عوض کنید.

### روش دوم: Service Account (سازمانی)
1. در Google Cloud Console سرویس‌اکانت بسازید و کلید JSON دانلود کنید.
2. روش «Service Account» را انتخاب و محتوای JSON را در کادر بچسبانید.
3. اگر «شناسه پوشه Drive» می‌دهید، پوشه را با ایمیل سرویس‌اکانت به اشتراک بگذارید (نقش Editor). اگر پوشه خالی باشد فایل‌ها در Drive خود سرویس‌اکانت ساخته می‌شوند.

### تنظیم بکاپ خودکار
- تب «بکاپ خودکار»: فعال/غیرفعال، فرمت (XLSX/CSV/JSON/TS)، بازه (روزانه/هفتگی/ماهانه)، ساعت اجرا به وقت تهران، انتخاب «چه داده‌هایی» و تعداد نسخه نگهداری‌شده.
- دکمه **«اجرای دستی بکاپ»** برای تست فوری. سابقه اجرا با وضعیت، حجم و لینک فایل در Drive نمایش داده می‌شود.
- پس از هر بکاپ موفق، نسخه‌های قدیمی‌تر از سقف نگهداشت خودکار حذف می‌شوند.

> **نکته Render رایگان:** سرویس پس از ۱۵ دقیقه بی‌کاری می‌خوابد و تایمر داخلی متوقف می‌شود. برای ساعت دقیق، یک cron بیرونی (مثلاً cron-job.org) هر ۵–۱۵ دقیقه `POST /api/integrations/scheduler/tick` با هدر `x-cron-secret` (مقدار `INTEGRATION_SECRET_KEY`) را صدا بزند — این درخواست هم بیدار می‌کند هم بکاپ سر ساعت اجرا می‌شود.

### چک‌لیست استقرار cron بیرونی (برای بکاپ قابل‌اتکا)

1. در پنل هاست، `INTEGRATION_SECRET_KEY` را با یک مقدار تصادفی ۳۲+ کاراکتری تنظیم کنید (`openssl rand -base64 32`) — این همان رمز cron است.
2. در پنل یکپارچه‌سازی‌ها، بکاپ خودکار را فعال کنید (فرمت/بازه/ساعت/دیتاست‌ها).
3. در سرویس cron بیرونی یک Job با این مشخصات بسازید:
   - URL: `https://<دامنه-سایت>/api/integrations/scheduler/tick`
   - متد: `POST`
   - هدر: `x-cron-secret: <مقدار INTEGRATION_SECRET_KEY>`
   - بازه: هر ۵ تا ۱۵ دقیقه
4. نمونه `curl` برای تست دستی:
   ```bash
   curl -X POST "https://your-app.onrender.com/api/integrations/scheduler/tick" \
     -H "x-cron-secret: YOUR_SECRET_VALUE"
   ```
   پاسخ موفق: `{ "ok": true, "running": false, "lastTick": "..." }`
5. تأیید: در پنل یکپارچه‌سازی‌ها → تب لاگ‌ها باید رویدادهای `BACKUP_DUE`/بکاپ ببینید؛ و «وضعیت آخرین بکاپ» در تب بکاپ باید سبز شود.
6. اگر بین دو هشدار تلگرامی «توقف بکاپ» بیش از ۱۲ ساعت فاصله می‌افتد، یعنی مشکل تکرارشونده است — لاگ‌ها را بررسی کنید. (هشدار `BACKUP_STALE` در رویدادهای تلگرام باید تیک خورده باشد؛ در پیکربندی‌های قدیمی باید یک‌بار از پنل فعال شود.)
7. راهنمای عملی برای هر هاست: `scripts/setup-cron.md` در مخزن.

## ۲) Google Sheets (اکسل آنلاین گوگل) — سه قدم

1. کلید JSON سرویس‌اکانت را در تب Sheets بچسبانید (همان فایل Drive قابل استفاده است).
2. یک Google Spreadsheet بسازید و در اشتراک‌گذاری، ایمیل سرویس‌اکانت را با نقش **ویرایشگر (Editor)** اضافه کنید.
3. **Spreadsheet ID** را از URL کپی کنید (`docs.google.com/spreadsheets/d/【این-بخش】/edit`)، نام تب را بنویسید و **«آزمایش اتصال»** بزنید.

سپس برای هر دیتاست (مشتریان، محصولات، تأمین‌کنندگان، تنظیمات):
- **نگاشت فیلدها**: نام ستون در شیت برای هر فیلد سامانه — برچسب فارسی پیش‌فرض است و قابل تغییر.
- **نوشتن در شیت**: داده‌های سامانه به شیت می‌رود (ر headers + ردیف‌ها).
- **ورود از شیت**: ابتدا «پیش‌نمایش»، سپس «اعمال» — رکوردها بر اساس کد/SKU به‌روزرسانی می‌شوند و داده تکراری دوباره ساخته نمی‌شود.
- **همگام‌سازی خودکار**: بازه به دقیقه (۰ = خاموش)؛ دیتاست‌های نگاشت‌شده هر بازه در شیت بازنویسی می‌شوند.

سفارش‌ها فقط خروجی دارند و ورود داده از شیت پشتیبانی نمی‌شود.

## ۳) تلگرام — بات اطلاع‌رسانی

1. **توکن بات**: در تلگرام به `@BotFather` پیام دهید → `/newbot` → توکن را کپی کنید.
2. **Chat ID**: برای چت شخصی به `@userinfobot` پیام دهید؛ برای گروه، بات را اضافه کنید و شناسه عددی (منفی) بگیرید؛ برای کانال، بات باید ادمین باشد.
3. توکن و Chat ID را ذخیره کنید و روی **«ارسال پیام تست»** بزنید.
4. رویدادهای قابل انتخاب: ثبت سفارش جدید، بکاپ موفق، خطای بکاپ، کم‌موجودی، مرجوعی جدید، خطای Sheets.
5. متن هر پیام قابل سفارشی‌سازی است — با متغیرهایی مثل `{{orderNo}}`، `{{customerName}}`، `{{total}}`، `{{error}}`.

## ۴) هوش مصنوعی (OpenRouter / 9Router / سفارشی)

- **OpenRouter**: کلید از `openrouter.ai/keys` — Base URL پیش‌فرض `https://openrouter.ai/api/v1` و مدل مثل `openai/gpt-4o-mini` یا مدل‌های free.
- **9Router**: کلید از داشبورد 9Router؛ Base URL مثل `http://localhost:20128/v1`.
- **سفارشی**: هر سرویس سازگار با OpenAI (Ollama، LM Studio و…) — فقط Base URL، کلید و نام مدل.
- «دستور سیستمی» (System Prompt) از پنل قابل ویرایش است.
- قابلیت‌ها: پاسخ به پرسش‌های مدیریتی بر اساس داده‌های سامانه، خلاصه وضعیت، دسته‌بندی خودکار محصولات با پیش‌نمایش و «اعمال همه».
- لاگ هر درخواست (بدون داده حساس) در تب لاگ‌ها و آمار خطاها در کارت وضعیت دیده می‌شود.
- خطای 429 (محدودیت نرخ) با پیام خوانا مدیریت می‌شود و می‌توان موقتاً از پنل خاموش کرد بدون اختلال در بقیه سامانه.

---

## ۵) ورود و خروج داده

- **خروجی**: هر دیتاست در چهار فرمت CSV / Excel (XLSX) / JSON / TypeScript. CSV دارای BOM است و در اکسل فارسی درست باز می‌شود.
- **ورود**: آپلود فایل → **پیش‌نمایش و اعتبارسنجی** (سطرهای معتبر، فهرست خطاها) → **اعمال نهایی**. حداکثر ۲۰۰۰ سطر و ۱۰ مگابایت.
- ستون‌ها با برچسب فارسی (یا نام انگلیسی فیلد) پذیرفته می‌شوند؛ همین فایل خروجی را می‌توان ویرایش و دوباره بارگذاری کرد.
- قواعد: رکورد بر اساس `code` (مشتری/تأمین‌کننده) یا `sku` (کالا) به‌روزرسانی یا ساخته می‌شود؛ برند و دسته‌بندی با نام ساخته می‌شوند؛ کلیدهای `seq:*` قابل ورود نیستند.

## ۶) دسترسی به سرویس‌های خارجی از داخل ایران

سرویس‌های گوگل، تلگرام و OpenRouter از داخل ایران بدون تغییر مسیر در دسترس نیستند. سه راهکار دارید؛ برای هر سرویس می‌توانید راهکار متفاوتی انتخاب کنید.

### دامنه‌هایی که باید در دسترس باشند

| سرویس | دامنه‌ها |
|---|---|
| Google Drive / Sheets / OAuth | `www.googleapis.com`، `oauth2.googleapis.com`، `googleapis.com` و `accounts.google.com` (صفحه رضایت OAuth) |
| تلگرام | `api.telegram.org` |
| هوش مصنوعی (OpenRouter) | `openrouter.ai` — اگر Base URL را عوض کنید، همان آدرس جایگزین (مثل آدرس 9Router) |

### راهکار ۱ — پروکسی خروجی داخل خود برنامه (توصیه‌شده)

برنامه از طریق متغیرهای محیطی زیر، درخواست‌های هر سرویس را از پروکسی HTTP عبور می‌دهد:

```bash
# عمومی — برای هر سه سرویس (اگر متغیر اختصاصی تنظیم نشده باشد)
HTTPS_PROXY="http://user:pass@proxy-host:port"

# اختصاصی هر سرویس (اولویت با این‌هاست)
GOOGLE_PROXY_URL="http://proxy-host:port"     # فقط googleapis.com و oauth2.googleapis.com
TELEGRAM_PROXY_URL="http://proxy-host:port"   # فقط api.telegram.org
AI_PROXY_URL="http://proxy-host:port"         # فقط OpenRouter / سرویس AI
```

- **فقط پروکسی HTTP/HTTPS پشتیبانی می‌شود** (تونل CONNECT). اگر فقط SOCKS5 دارید، با ابزار سطح سیستم (مثل `gost` یا `privoxy`) آن را به HTTP محلی تبدیل کنید.
- برای **Service Account** گوگل، کتابخانه `google-auth-library` خودش `HTTPS_PROXY` را می‌خواند — همان متغیر عمومی کافی است.
- متغیرها را در پنل هاست (Environment) تنظیم کنید؛ روی Render در Settings → Environment. پس از تغییر، سرویس را Deploy مجدد کنید.
- اگر پروکسی قطع شود، خطای فراخوانی در تب «لاگ‌ها»ی پنل یکپارچه‌سازی‌ها با پیام شبکه دیده می‌شود.

### راهکار ۲ — تغییر Base URL برای هوش مصنوعی

ساده‌ترین راه برای AI: از پنل، Base URL را به یک درگاه در دسترس تغییر دهید (مثل آدرس 9Router، یک Reverse Proxy شخصی یا هر سرویس سازگار با OpenAI). کلید و مدل را هم همان‌جا تنظیم کنید — بدون نیاز به پروکسی.

### راهکار ۳ — سرویس خروجی یا VPS

- یک VPS خارج از ایران با Nginx به‌عنوان Forward Proxy (HTTP CONNECT) راه‌اندازی کنید و آدرس آن را در `HTTPS_PROXY` بگذارید — **حتماً با احراز هویت و محدودیت IP**، چون proxy باز یک حفره امنیتی است.
- یا از سرویس‌های «خروج» تجاری استفاده کنید و آدرس پروکسی آن‌ها را در همان متغیرها بگذارید.

## امنیت

- کلید رمزنگاری از متغیر محیطی `INTEGRATION_SECRET_KEY` خوانده می‌شود (حداقل ۳۲ کاراکتر تصادفی). تغییر کلید یعنی باید اتصال‌ها را دوباره تنظیم کنید.
- همه توکن‌ها و کلیدها فقط رمزنگاری‌شده ذخیره می‌شوند و هرگز در کد/مخزن/لاگ قرار نمی‌گیرند؛ در API فقط نسخه mask شده برمی‌گردد.
- همه تغییرات در «سوابق سیستم» (Audit) ثبت می‌شود و دسترسی فقط با مجوز `users.manage` (مدیر کل) امکان‌پذیر است.
- «قطع اتصال» همه داده‌های حساس آن یکپارچه‌سازی را کامل حذف می‌کند.
